## 上传前必须人工完成

- [ ] 将隐私政策发布到公开 HTTPS 地址，并把 URL 填入后台
- [ ] 确认开发者名称、邮箱和网站所有权信息准确
- [ ] 在“成熟内容”中选择“是”（OnlyFans 集成）
- [ ] 选择发布地区、可见性与延迟发布策略
- [ ] 删除未使用的 `webRequest` 权限，或记录其确切运行时用途
- [ ] 决定是否保留 `file:///*`；如非核心功能，建议删除以缩小权限范围
- [ ] 将真实公开主页上的实际运行截图替换/补充到最多 5 张，避免任何成人、个人或版权敏感内容
- [ ] 验证商店后台披露、隐私政策和实际代码行为完全一致
- [ ] 上传由 `extension/` 内容打包的 ZIP，ZIP 根目录必须直接包含 `manifest.json`
- [ ] 用全新 Chrome 配置文件安装并测试最终 ZIP/CRX

## 当前阻断项/高风险项

1. `manifest.json` 中声明了 `webRequest`，但代码没有调用该 API；这是最小权限审核风险。
2. `file:///*` 是广泛主机权限且需要用户手动开启。若本地 HTML 扫描不是首发核心功能，建议移除。
3. OnlyFans 属成人导向网站集成，必须标记成熟内容；商店不允许露骨素材，也不应暗示绕过付费墙。
4. 平台页面结构和媒体接口经常变化，最终包必须在提交当天再次做端到端测试。
5. 现有 `extension.zip` 含构建/浏览器生成文件的可能性较高；应使用干净打包脚本重新生成提交包。
